# 评估协议与复核边界

本仓库分为原课程方法与后续简化工程示例。二者的分类器、筛选方法、参数搜索和阈值策略不同，不能把两者分数差解释为单个评估修正带来的变化。

## 原方法

原方法为 mRMR / ICC / 先验权重筛选、L1 通道组内 PCA + LR、L2 原始特征与交互特征 + XGBoost / SVM 择优。二层阈值在分组内层验证上选择。外层为按 image_id 分组的五折验证；PCA、监督筛选和交互排序在外层训练集上学习。

需要区分两个问题：特征处理先于**内层**划分，会让内层选择分数存在信息复用；但只要外层测试数据没有参与这些有监督处理，它不等于外层测试标签直接进入了训练。不能仅据此认定原外层 Macro-F1 被抬高了多少。本次保留原模型选择策略，再单独检查可能涉及外层测试信息的环节。

### 成对检查

1. 原评估函数用真实标签决定哪些测试行计算交互特征，其余行填零。复核时保留原预测，再对同一个训练出的分类器、同一批测试行计算不依赖标签的交互特征，比较逐行预测和指标。
2. 原 ICC 表由全体特征样本计算。另跑仅在每个外层训练折计算 ICC 的配置，保持模型、筛选参数、搜索网格和阈值流程不变。
3. 在第二项基础上，分别关闭 L1 PCA 或交互特征，记录相同折划分上的配置差异。这是当前数据上的消融结果，不等于跨数据集或统计显著性的证明。

具体数字以 [复核报告](../reports/reassessment/README.md) 为准。原始文件保持不变；专用脚本通过可核对的函数插桩获得成对预测，并记录来源文件校验值。

### 其他实现限制

- 原数据按原图 ID 分组，没有患者或真实病灶来源 ID；不同原图间无完全相同像素，不排除患者层面的相关性。
- 原 `clean_features` 在全表上删除常数列并处理缺失值。本次会报告实际缺失情况；不能在没有数据的情况下假定该步骤一定造成明显分数提升。
- 原交互函数返回候选全集，但分类器推理时按训练保存的交互列取值；候选全集本身不等于训练/测试特征错配。其比值分母包含批次统计，仍有工程改进空间。
- 原交互候选的 F / RF 排序归一化可能受到常数列与 NaN 影响，因此统计候选族不应被解释为经过验证的病理类别。
- 原 L1 阈值搜索受到局部导入作用域影响，异常被捕获后实际保留默认 0.5；L2 阈值搜索正常执行。本次忠实保留该行为，不将它作为已生效的优化贡献。
- 原 `l2_pca` 参数没有在评估函数中实际用于二层变换。当前方案保持原值 False；本次不通过切换该参数声称完成全局 PCA 对照。
- 历史上做过多轮配置选择；再次得到相同的交叉验证成绩属于复现，不是新的独立测试集验证。

## 简化工程示例

`src/skin_lesion_ml/` 中的代码使用更小的模型网格、LR → SVM 路径，并把整套特征处理放入每个内层训练折。它适合演示可复用接口和严格的折内处理，但不是原方法的等价实现。

其 F-test 配置下得到的层次模型 Macro-F1=0.706，仅对应这套简化配置。此前将该结果放在首页主体、弱化原版成绩的做法无法体现原方法的实际表现；本次以原配置的复核结果重新评价。旧结果仍保留在 [工程示例说明](../ENGINEERING.md) 和 `reports/validation/` 供追溯。
